# pain001 v0.0.83

## Highlights ⭐️

* **Verify against a trust anchor**: `verify_signature()` returns a `SignatureReport` and needs the signer's certificate or public key, or an explicit `trust_embedded_cert=True` for an integrity-only check. `pain001 verify-signature FILE --cert PEM` does the same from the command line.
* **Signatures from other tools verify**: verification now uses exclusive C14N 1.0 on the parsed document, as the signature declares. A valid signxml signature that 0.0.82 rejected with a digest mismatch now passes, and CI signs and verifies both ways with signxml and xmlsec1.
* **RSA-PSS and ECDSA**: sign with `rsa-pss-sha256`, `ecdsa-sha256` or `ecdsa-sha384`, chosen by the key or `--xml-sign-alg`. RSA-SHA256 signatures are byte-identical to 0.0.82.
* **Breaking changes announced a release ahead**: the release preflight refuses a change to generated XML that the previous release did not announce.

## Details

Two changes are announced for 0.0.84 in the CHANGELOG's `Announced`
section and ADR-0012: `verify_xml_signature()` without a key or
certificate, which trusts the certificate inside the document and now
warns, will be refused; and `sign_xml_document()` will sign the
document as given, keeping its namespace prefixes instead of rewriting
a default namespace as `ns0:`. The `sign` extra now installs `lxml`.
The pyarrow bound for the `parquet` extra moves to `>=26.0.1,<27`.
Certificate chains and validity dates are not checked.
