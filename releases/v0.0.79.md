# pain001 v0.0.79

## Highlights ⭐️

* **Mixed-currency batches are flagged**: the `xborder-ct` profile reports `XB-CCY-MIX` for a row whose currency differs from the batch's. Every row goes into one PmtInf, so a mixed EUR/USD batch produced a block CtrlSum that added the two currencies together. Generated XML is unchanged; split such a batch into one file per currency.
* **SSH certificates and agent keys for upload**: `pain001 upload --certificate` presents an OpenSSH certificate after checking locally that it belongs to the key and is still valid, and `--use-agent` keeps ssh-agent keys on offer alongside a key file or password. DSA and FIDO keys, and a wrong passphrase, are now named instead of reported as a key-format error.
* **Every public function and command has an example**: six new examples cover faces, the Business Application Header and XML signing, streamed output, the template registry and typed errors, the plugin and upload commands, and a running REST server. A test fails when a public name or command has none.
* **In lockstep with the whole suite**: pain001-mcp, pain001-lsp, pain001-loader-xlsx and pain001-loader-mt101 ship 0.0.79 too.

## Details

`parse_pain002_report` now returns every transaction in a partially
accepted report (it kept only the first of each payment block, so other
rejections were lost), and `parse_camt053_statement` returns every
statement and reads the camt.053.001.08 entry status. Config files,
environment variables and profiles now set streaming and chunk size,
which the CLI's own defaults used to override. `--decrypt-key` no longer
imports the key into your default GnuPG keyring. The async wrappers take
every option of their synchronous versions, XML signing declares its
dependency as the `sign` extra, and the documentation was checked claim
by claim against the code. pain.001 output, the CLI's existing options
and the REST routes are unchanged from 0.0.78.
