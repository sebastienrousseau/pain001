# pain001 v0.0.81

## Highlights ⭐️

* **One file, one batch**: rows that disagree on a debtor-level column (debtor, account, agent, execution date, charge bearer and the like) are refused with the column and row named. Before, they were written under the first row's debtor. `validate` refuses the same files, so a file that validates also generates.
* **Nothing unchecked reaches disk**: every file is staged, checked (XSD, then Schematron when asked) and renamed into place, so a refused or interrupted run never leaves a partial file. Streamed chunks get their own MsgId (`<id>-<n>`).
* **IBANs and BICs checked on every load**, with or without `--scheme`, naming the row and column but never the value; `--no-identifier-checks` opts out. The SEPA profiles now require charge bearer `SLEV`, as the EPC implementation guidelines do.
* **Safer, faster server**: `pain001 serve` refuses a network bind without `PAIN001_API_KEY` unless `--insecure` is given, REST pipelines run on a bounded thread pool off the event loop, and JSON Schema validation is about 30x faster on 1,000 rows.

## Details

Five changes refuse input or start-up that 0.0.80 accepted; the
`Breaking` section of the CHANGELOG lists each with its fix or opt-out.
Generated XML for valid single-batch input is unchanged.
