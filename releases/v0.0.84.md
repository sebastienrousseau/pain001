# pain001 v0.0.84

## Highlights ⭐️

* **Verify the complete ecosystem**: one read-only audit checks all nine GitHub releases, five PyPI distributions, four multi-platform GHCR images, the MCP Registry and the deployed website. A missing or partial publication fails with the affected member named in its JSON report.
* **Check after publishing**: daily and post-publication workflows use the same inventory and retain their evidence. Companion workflows call an immutable core action without a cross-repository dispatch credential.
* **Current component documentation**: README and roadmap tables derive from the checked inventory, including the scaffold, native extension and website. Release guidance requires actual publication evidence for every member.

## Details

The offline publication tests enforce a separate 100% line and branch
coverage floor. Existing package coverage and mutation thresholds remain
unchanged. Signed tag identity, release titles and checksum notes, registry
hashes and dependency floors, container architectures and source labels,
and the deployed browser wheel hash are checked explicitly. The scheduled
check uses GitHub asset digests; full artifact downloads and cryptographic
build attestations remain part of release verification.
