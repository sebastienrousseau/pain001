# pain001 v0.0.84

## Highlights ⭐️

* **Verify the complete ecosystem**: a read-only audit checks all nine GitHub releases, five PyPI distributions, four multi-platform GHCR images, the MCP Registry and the live website. Daily and post-publication workflows retain reports and fail incomplete rollouts.
* **Explicit trust in the legacy verifier**: `verify_xml_signature()` now requires the caller's public key or certificate, as announced in 0.0.83. An embedded certificate alone no longer makes that call succeed; explicit integrity-only checks remain available through `verify_signature()`.
* **Preserve signed XML namespaces**: the signer uses exclusive C14N 1.0 on the parsed document and keeps its namespace prefixes. With a head.001.001.03 header, it places the signature in `AppHdr/Sgntr` and covers the complete envelope, following accepted ADR-0012.
* **Current component documentation**: README and roadmap tables derive from the publication inventory, including the scaffold, native extension and website. Package coverage and mutation thresholds remain unchanged.

## Details

The offline publication tests enforce a separate 100% line and branch
coverage floor. Existing package coverage and mutation thresholds remain
unchanged. Signed tag identity, release titles and checksum notes, registry
hashes and dependency floors, container architectures and source labels,
and the deployed browser wheel hash are checked explicitly. The scheduled
check uses GitHub asset digests; full artifact downloads and cryptographic
build attestations remain part of release verification.
