# pain001 v0.0.87

## Highlights ⭐️

* **A refusal is never a 200**: `POST /api/v1/generate` and
  `/api/v1/ui/generate` answer `422` with the findings when they refuse the
  data, and a `200` always carries the XML. This is a breaking change for
  clients that read only `success`; the conformance kit moves to version 2.
* **One validation verdict everywhere**: The CLI, the REST API,
  `process_files` and the new `pain001.generate` and `pain001.validate`
  run the same checks in the same order, refuse rows that break the
  message type's JSON Schema, and demand only the columns that type needs.
* **A safer default REST API**: Without `PAIN001_API_KEY` the API answers
  only requests addressed to loopback, cancelling a job stops it, the rate
  limiter keys on the real client behind trusted proxies, and every
  response carries an `X-Request-ID` that the logs and traces share.
* **A scriptable CLI**: Every command that returns a result takes
  `--format json`, standard output carries only that result, and a
  mistyped command suggests the one you meant.
