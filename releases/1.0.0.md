# Pain001 Release 1.0.0

**Release Date:** 2026-06-16
**Tag:** v1.0.0
**Python:** 3.10+
**Status:** Stable — first release under [Semantic Versioning](https://semver.org)

## Executive Summary

**1.0.0 is the first stable release of Pain001.** From here the public API
(top-level exports, the CLI, the REST `/api/v1` surface, and the library
functions) follows Semantic Versioning.

The flagship capability is **scheme-aware validation**: until now Pain001
proved a payment file was *well-formed* (XSD-valid); it could not prove the
payment obeyed the rules of the scheme it would clear through. A file can
pass the XSD and still be rejected by the bank for being in the wrong
currency, carrying an invalid IBAN, or using characters outside the ISO
20022 set. This release closes that gap and rounds out the developer surface.

### What's in 1.0.0 at a glance

- **Scheme validation** — `sepa-sct`, `sepa-sdd`, and `sepa-inst` rulebooks
  on top of XSD, with structured, per-row violations and remediation hints.
- **Unified CLI suite** — `generate` / `validate` / `versions` / `inspect` /
  `init` / `serve` / `mcp`, with the legacy `pain001 -t … -d …` still routed
  to `generate`.
- **REST API portal** — versioned `/api/v1`, optional rate limiting, a
  durable job store, enriched OpenAPI, and an interactive Scalar reference.
- **MCP server** (`pain001-mcp`) — generation/validation as tools for LLM
  clients.
- **LSP server** (`pain001-lsp`) — live payment-CSV diagnostics in editors.
- **Hardening** — all bundled sample data now passes the library's own
  validators (guarded in CI); governance docs reduce bus-factor risk.

## New Features

### Scheme rulebook validation

`pain001.validation.validate_scheme(rows, profile="sepa-sct")` validates
loaded payment rows against a payment-scheme rulebook and returns
structured, per-row results:

```python
from pain001 import validate_scheme

result = validate_scheme(rows, profile="sepa-sct")
if not result.is_valid:
    for v in result.violations:
        print(v.index, v.rule, v.field, v.message)
```

The first profile, **`sepa-sct`** (SEPA Credit Transfer), enforces:

- EUR currency (`SEPA-CCY`)
- valid debtor/creditor IBANs — ISO 13616 / mod-97 (`SEPA-DBTR-IBAN`,
  `SEPA-CDTR-IBAN`)
- well-formed BIC when supplied, optional otherwise (`SEPA-BIC`)
- the SEPA amount ceiling of 999,999,999.99 and 2-decimal precision
  (`SEPA-AMT`)
- ISO 20022 character set and field-length limits (`SEPA-CHARSET`,
  `SEPA-LEN`)
- a warning when the service level is not `SEPA` (`SEPA-SVCLVL`)

A second profile, **`sepa-sdd`** (SEPA Direct Debit, pain.008), reuses the
shared SEPA rules and adds mandate id (`SDD-MNDT`) and sequence type
(`SDD-SEQTP`) checks. New profiles plug in through the `ValidationProfile`
base class and the `PROFILES` registry. The full rule catalogue lives in
[SCHEMES.md](../SCHEMES.md).

### ISO 20022 character-set guard

`is_valid_charset`, `find_invalid_characters`, and `sanitize_to_charset`
detect and transliterate characters outside the restricted Latin set
(`Café` → `Cafe`), a leading cause of real-world bank rejections.

### CLI

```bash
pain001 -t pain.001.001.03 -d payments.csv --scheme sepa-sct --dry-run
pain001 -t pain.001.001.03 -d payments.csv --scheme sepa-sct --explain
pain001 -t pain.001.001.03 -d payments.csv --scheme sepa-sct --scheme-format json
```

Runs the rulebook on top of XSD validation in both dry-run and generation,
prints per-row violations, and exits `1` on failure (`2` for an unknown
profile). `--explain` adds a remediation hint per violation;
`--scheme-format json` emits a machine-readable result for CI.

### REST API

`POST /api/v1/validate` and `POST /api/v1/generate` accept an optional
`scheme` field and return `scheme_violations`; generation is refused when
scheme validation fails.

## Upgrade Notes

Fully backward compatible — scheme validation is opt-in. Upgrade with:

```bash
pip install --upgrade pain001
```

Python 3.10 or newer is required.
