# pain001 v0.0.66

Two roadmap features land and four issues that were already mostly
shipped are closed out. Generation behaviour is unchanged unless you
opt into the new profile.

## Cross-record duplicate detection

`--scheme anti-duplicate` flags rows in a batch that share the same
creditor IBAN, amount and requested execution date, which is what a
payment keyed in twice looks like. Every row in the group is reported
with `DUP-CREDITOR-DATE` and the indices of its partners. Matching is
exact-key: amounts are bucketed to the currency's minor unit, IBANs are
compared without whitespace or case, and a one-cent difference is a
different payment.

Profiles now compose. `--scheme sepa-sct,anti-duplicate` runs both and
reports the union; the same spelling works in the REST `scheme` field
and the MCP `profile` argument.

## A dashboard for people who will not open a terminal

`/api/v1/ui` is one HTML file served by the REST API: drop a CSV, pick
the message type and rulebooks, validate, generate, download. No
framework, no build step, no CDN, no new dependency. The upload never
touches the server's disk. Locked by `PAIN001_API_KEY` like every
route; `PAIN001_UI_DISABLED=1` switches it off. Beta.

## Closing the gaps

- `--decrypt-key <keyfile>` and `--decrypt-passphrase-env <VAR>` on
  `generate` and `validate`, the two GPG flags the issue specified.
- A traced run now shows `pain001.generate`, `pain001.write`,
  `pain001.render` and `pain001.validate`; scheme checks and every REST
  handler are spans too, and the SDK is bootstrapped at server start.
- `requirements.txt` moves to xmlschema 4.3.2 so elementpath 5 resolves
  and the Docker image builds.
