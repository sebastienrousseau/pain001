# pain001 v0.0.67

The first of the three example-corpus releases planned in
[ADR-0003](../docs/adr/0003-example-corpus-two-corpora-one-engine.md):
the ground cleared, the engine built, the schema coverage corpus complete
for every bundled XSD, and the first three market files shipped with
provenance. Every item below is in [CHANGELOG.md](../CHANGELOG.md) with
its detail; this page is the tour.

## Ground clearing (WS0)

- The twelve bundled `<type>.xml` examples had drifted from their own CSVs
  (wrong transaction counts, amounts without minor units, a hand-edited block
  no template emits). They are regenerated and pinned by a byte-exact test;
  the regeneration scripts walk the template registry and take `--check`.
- Four hand-typed required-column lists disagreed. One contract now derives
  from the bundled JSON schemas and feeds the CSV validator, the SQLite
  validator and the LSP diagnostics.

## Inventory, deltas, code sets, pain.008.001.08 (WS1)

- `pain001.corpus.inventory` walks a bundled XSD into every element path,
  attribute, `xs:any` slot and choice branch with facets and cardinalities;
  `coverage()` measures a file set against it.
- `docs/message-deltas.md` is generated from the inventories: what each
  edition changed, .03 through .13 and pain.008 .02 to .08.
- The ISO external code sets (edition 2Q2026 v3) ship with a loader and a
  refresh script that refuses to drop a code bundled data still uses.
- `pain.008.001.08`, the direct-debit edition the EPC 2025 rulebooks and
  CBPR+ carry, is a bundled message type.

## Scenarios, builder, identifiers, overlays (WS2)

- A scenario says what a payment is; `pain001.corpus.builder` spells it per
  edition from the inventory (renames, choice wrapping, caps, drops, all
  reported) and validates the result. The same scenario renders valid .03
  and .09.
- Synthetic identifiers pass every structural check: IBANs in each market's
  BBAN shape with national check digits, test-form BICs, ISO 17442 LEIs,
  ABA numbers, UETRs.
- The overlay assertion grammar shared with `iso20022-bank-profile-mcp`
  reads that project's files unchanged and adds `forbidden`, `one_of`,
  `max_length`, `matches` and `charset`.

## Schema coverage corpus (WS3)

- Thirteen sets, generated from the inventories along the MDR rules, at
  100 % of element paths and choice branches, every file schema-valid and
  MDR-clean; `make corpus-coverage` is strict and part of `make check`.

## MDR rules, rail profiles, validation ladder (WS4)

- Every constraint the ISO MDR defines for pain.001 (20) and pain.008 (9),
  quoted from the report, in `pain001.corpus.rules.mdr`.
- Eighteen rail profiles (`uk-chaps`, `us-ach`, `ch-domestic`,
  `cbpr-cross-border` …) and five country purpose mandates, composable with
  the SEPA profiles and exposed through CLI, REST, MCP and the dashboard.
- Every market file passes L0 to L3 (XSD, MDR, profiles, overlays); the
  result is in its provenance sidecar; `make corpus-evidence` and
  `scripts/corpus_evidence.py record` carry external validator runs into
  provenance.

## Docs (WS9)

- [docs/corpus.md](../docs/corpus.md): how to read a scenario, the ladder,
  how to add a country, the evidence policy, the rulebook watch.

## Coordinated releases

Adding `pain.008.001.08` is a suite-wide change: `pain001-mcp` and
`pain001-lsp` list the new type in their own releases once this one is on
PyPI, alongside the lockstep bump from 0.0.65.

## Upgrade notes

- `id` in payment rows is validated as text (the XSD's Max35Text), so
  `MSG001` is accepted where the old validator demanded an integer.
- The LSP `missing-column` diagnostic reports the JSON schema's list for
  the file's message type, which is longer than the previous 7-column
  minimum; the bundled sample CSVs satisfy every version.
- The scheme registry grows from six to twenty-nine profiles; code that
  pinned the exact set must read `pain001.validation.PROFILES`.
