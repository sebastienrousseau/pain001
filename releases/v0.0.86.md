# pain001 v0.0.86

## Highlights ⭐️

* **Truthful pain.002 status**: Build a pain.002 report with several
  transactions in one payment block, as a bank's reply does, and get every
  report validated against its bundled schema. The status command now counts
  rejected transactions, naming rejected groups and payment blocks separately.
* **A conformance kit for the SDKs**: The Java, Go, Rust, .NET and C++ SDKs
  share one list of requests to send to a running `pain001 serve` and what
  each response must satisfy, with synthetic fixtures and a normalised
  OpenAPI snapshot that fails CI when it drifts.
* **No reply deleted unread**: With `--after-fetch delete` or `move`, the
  download command reads and hashes every file before touching the remote
  copy, so a reply reissued under the same name and size is kept.
* **A harder REST API and CLI**: The API refuses oversized bodies, caps
  active jobs, adds a readiness check and masks account data in row errors.
  The CLI reports each row error by line, column and a stable code, and
  `--verbose` shows library logs.
