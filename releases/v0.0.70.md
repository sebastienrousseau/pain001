# pain001 v0.0.70

A small release found by running the example corpus through the library
in a browser: two things the package did on import that it should do on
use, and one vocabulary gap between the rail rules and the CSV pipeline.

## Rail rules read the CSV pipeline's column names

The rail profiles looked for `creditor_account_id`, `creditor_town` and
`creditor_country`. The records twin and `docs/input-columns.md` write
`creditor_account_number`, `creditor_town_name` and `creditor_country_code`,
so `--scheme` on a pipeline CSV reported a missing account number or
address for values the rows carried. Both spellings now satisfy the
account and address rules; the flagged field name stays the short one.

## Optional dependencies load when used

`import pain001` no longer imports the command-line module, so `rich`
stays out of a program that only generates and validates files;
`pain001.main` resolves lazily. The corpus builder imports `lxml` inside
the two functions that serialise, and the SQLite loader imports
`sqlite3` when a database is opened. In a WebAssembly runtime the wheel
set the library needs drops from about 13 MB to under 5 MB.

## Upgrade

```sh
pip install --upgrade pain001
```

No API changes. Programs that imported `pain001.main` keep working.
