# pain001 v0.0.82

## Highlights ⭐️

* **`pain001 check` on files you already have**: the bundled XSD of the message type the namespace names, the cross-element rules, and `--scheme`, `--rules` and `--schematron` when given. Text, JSON or SARIF, exit 0, 1 or 2. The same check runs from `POST /api/v1/check`, the MCP server, a GitHub Action (`action.yml`) and pre-commit hooks.
* **Faster**: compiled templates are cached (a small call drops from 8.9 ms to 0.7 ms), `--help` starts in about 120 ms instead of 320 ms, and `--workers N` builds streamed chunks in parallel (40,000 rows in 0.9 s instead of 1.6 s with four workers).
* **.04 to .08 write what the input says (breaking)**: a valid IBAN is written as `<IBAN>` instead of `<Othr><Id>`, and a non-empty `service_level_code` as `PmtTpInf/SvcLvl/Cd`, as .03 and .09 to .13 already do. Other account values, and input without a service level, render as before.
* **Schematron that judges what it should**: the bundled rulebooks run on every pain.001 version (they passed .04 to .13 without running a rule), the SEPA rulebook accepts the service level and charge bearer on every transaction as EPC allows, and the new EPC-SCT-008 rejects a non-SEPA service level on a transaction.

## Details

For the same input, .04 to .08 output changes only where an IBAN or a
service level is involved; the CHANGELOG's `Breaking` section and
ADR-0011 explain both. A file that passed `--schematron sepa` can now
fail EPC-SCT-008, or EPC-PMT-002 when one of several batch service
levels is not `SEPA`. The CLI starts again on a base install without
the `api` extra, which 0.0.81 required. Every release now attaches
`pain001-<version>.facts.json` for the site and the MCP manifests.
