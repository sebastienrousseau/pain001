# pain001 v0.0.78

## Highlights ⭐️

* **Faces**: `project_face` and `pain001 face` project a pain.001 document into the UK Open Banking v4.0.1 domestic payment, Berlin Group NextGenPSD2 v1.3.16 payment initiation, or ISO 20022 element names, with a loss report of every source element not carried. A face refuses a document that lacks an element its target requires instead of inventing one.
* **On every surface**: `GET /api/v1/faces` and `POST /api/v1/faces/{face}` on the REST API, the `list_faces` and `project_face` tools in pain001-mcp, and the `pain001.faces.list` and `pain001.faces.project` commands in pain001-lsp.
* **Client documents as text only**: every surface goes through `project_face_text`, which refuses a server path, entity declarations and external references, and documents over 10 MiB.
* **In lockstep with the whole suite**: pain001-mcp, pain001-lsp, pain001-loader-xlsx and pain001-loader-mt101 ship 0.0.78 too.

## Details

Every face payload the corpus produces is validated in CI against the
target's published request schema, fetched at a pinned revision and
SHA-256 and never vendored. The ISO 2018 face's names come from the ISO
20022 Message Definition Reports, with five tags left unresolved rather
than guessed. The REST API's OpenAPI metadata moved to
`pain001/api/meta.py`; nothing served changes. pain.001 output and the
existing CLI and REST routes are unchanged from 0.0.77.
