# pain001 conformance kit

The kit pins what every pain001 SDK (Java, Go, Rust, .NET, C++) must do
against a running `pain001 serve`. Each SDK repository vendors this
directory byte for byte, runs every case through its own client in CI,
and fails if any case fails. Core runs the same cases in-process
(`tests/test_conformance_kit.py`), so the kit is proven against the
server it describes. All data is synthetic.

## Files

- `cases.json`: the cases (format below).
- `fixtures/`: request payloads, generated by `pain001 init` and
  `pain001 generate`; the bad-IBAN file differs from the good one by one
  check digit, and the bad-LEI file adds a `debtor_lei` column whose
  synthetic LEI (unassigned `0000` prefix) has a broken check digit.
  The CHAPS file is one synthetic GBP payment executed on 1 December
  2027 with no purpose code, which the `uk-chaps` rail refuses. The
  bad-currency file differs from the good one by its first row's
  currency (`EURO`), which the message type's JSON Schema refuses.
- `openapi.json`: the server's OpenAPI document at this kit version, for
  generating or checking client types. `tests/test_conformance_kit.py`
  fails when it drifts from the running app.

## Case format

Each case has an `id`, an HTTP `method`, a `path`, an optional JSON
`body` and an `expect` object.

- In `body`, an object `{"$file": "fixtures/<name>"}` is replaced by the
  text of that file (UTF-8), relative to this directory.
- `expect.status`: the HTTP status code, exactly.
- `expect.equals`: JSON Pointer (RFC 6901) to a JSON value; the value at
  the pointer must equal it (deep equality; `""` is the whole document).
- `expect.types`: JSON Pointer to one of `string`, `number`, `integer`,
  `boolean`, `array`, `object`, `null`.
- `expect.contains`: JSON Pointer to a list of strings; the value at the
  pointer must be a string containing each of them.

A missing pointer target fails the case. Cases never pin the server's
version or timestamps.

## Versioning

`kit_version` rises when a case changes meaning. The kit ships with
each pain001 release from 0.0.86; an SDK at version 0.0.N vendors the
kit from core 0.0.N.

## Changes

- **Kit 2 (pain001 0.0.87).** Breaking: `POST /api/v1/ui/generate`
  answers `422` instead of `200` when it refuses the data, with the
  same body (`success: false`, `xml: null`, and `validation_errors` or
  `scheme_violations`). New cases `generate-refused-rows` (fixture
  `bad-currency.pain.001.001.09.csv`) and `generate-refused-scheme`
  pin it. A `200` from generate now always carries the XML. An SDK
  whose typed generate call raises on any non-2xx must still give the
  caller the findings from that body, not only its `detail` (there is
  none). Also new since kit 1, without changing any case's meaning:
  `validate-bad-lei` and `validate-chaps-purpose-required`.
- **Kit 1 (pain001 0.0.86).** First release.
